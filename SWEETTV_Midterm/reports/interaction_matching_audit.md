# Interaction Matching Audit — Stage 2

Generated by `src/build_stage2_reports.py` from `reports/match_diagnostics.json`,
`reports/coverage_diagnostics.json` and `reports/interaction_statistics.json`.
**Everything here is provisional.** No threshold and no multiple-match strategy
has been selected. No test-period viewing behaviour was used (there is none).

## 1. Matching method

- Join key: `viewing.vsetv_id = schedule.channel_id`.
- Temporal test: `overlap = max(0, min(view_end, programme_end) - max(view_start, programme_start))`,
  with `programme_end = programme_start + duration` and `view_end = stop_time`.
- An **event** is one `(viewing session, schedule airing)` pair with
  `overlap > 0`.
- Schedule scope: union of the weeks 11–20 and 21–30 exports. Within a channel
  the exports hand over at the broadcast-day boundary and do not repeat slots
  (1 cross-export interval overlap found,
  both rows unlabelled), so the union is a near-continuous timeline and avoids
  both lost matches and duplicated joins at 2020-05-18.
- Offset applied: **0 seconds**.
- Implementation: stdlib CSV streaming, compact per-channel `array` index, and
  a disk-backed SQLite event store. No pandas, no full-file object model.

## 4. Matching strategies (applied after the threshold filter)

|---|---|

### 4.1 Advantages and disadvantages

- **A — keepall.** Highest recall and preserves genuine co-viewing / zapping
  evidence; a session that straddles two programmes contributes to both. Cost:
  multi-label noise, interactions depend on programme length (long films
  accumulate more overlapping sessions), and pair counts are inflated by
  short zaps. Multi-match sessions are
  27.1% of
  matched sessions at rule B.
- **B — maxoverlap.** One interaction per session, robust when programme
  boundaries are slightly uncertain and when one airing is clearly dominant;
  favours long programmes because absolute overlap grows with exposure.
  Compared with C it keeps more sessions for long programmes and fewer for
  short ones.
- **C — maxratio.** One interaction per session, normalises by programme
  length, so a short programme watched fully can beat a long film watched for
  the same time. More sensitive to schedule/clock errors near boundaries and to
  very short programmes (a 60 s minimum plus 20% is easy to satisfy on a
  5-minute item).
- B and C produce the same event count at each rule (one per session) but differ
  in which programme is chosen: at rule B, pair counts differ by
  7,846
  and programme coverage by 1.
  Neither dominates; the choice changes which items receive credit.

Observations:

- Raising the coverage requirement from 10% to 20% at 60 s removes
  500,899 events
  (24.7%) and
  173,032
  unique pairs. Raising the floor from 60 s to 120 s at 20% removes only
  3,126 events —
  the ratio, not the floor, is the binding constraint at that point.
- Rule D keeps 43.6% of rule-A events but raises
  the median overlap ratio from 0.414 to
  0.966. It is much more conservative and much more
  skewed towards long sessions.
- Even the loosest rule leaves 24
  users with no interaction and 3994
  programmes with no interaction, out of 4,914 users and 8,233 labelled
  programmes in the training schedules.
- All rules reduce the interaction distribution very unevenly: the
  programme-level median is far below the mean
  (93 vs 478.9),
  so popularity-style skew is present in every candidate.

No rule is selected. `reports/threshold_sensitivity.csv` contains the full grid.

## 7. Provisional interaction datasets

Location: `outputs/provisional_interactions/` — **provisional, not final**.
Twelve datasets, one per (strategy, rule), named
`strategy{A|B|C}_{keepall|maxoverlap|maxratio}__rule{A|B|C|D}_{seconds}s_{percent}pct.csv.gz`.

Columns:

| Column | Meaning |
|---|---|
| `user_id` | Exact viewing-log user string |
| `tv_show_id` | Exact non-zero schedule programme ID string |
| `n_overlap_events` | Number of surviving (session, airing) events for the pair |
| `n_sessions` | Distinct viewing sessions for the pair |
| `total_overlap_seconds` | Sum of overlap seconds |
| `mean_overlap_ratio`, `max_overlap_ratio` | Overlap / programme duration |
| `first_view_start`, `last_view_start` | Observation-window bounds for the pair |

`metadata.json` records the exact rule and strategy definition, file sizes and
SHA-256 for every dataset, and states that nothing is final.
